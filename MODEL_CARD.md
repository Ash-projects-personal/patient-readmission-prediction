## Intended use

**Primary use case.** Educational demonstration of an end-to-end clinical risk modeling pipeline: feature engineering on EHR style tabular data, gradient boosted classification, and SHAP based explainability presented through a Streamlit interface.

**Out-of-scope uses.** This model is **not** intended for, and must not be used for, any of the following:
- Real clinical decision-making, triage, or treatment planning
- Discharge planning or insurance authorization
- Any deployment in a hospital, clinic, payer, or other healthcare delivery setting
- Any decision affecting an individual person's care

## Training data

- **Demo pipeline (`train_model.py`).** 50,000 synthetic rows generated by the script itself from hand written random distributions. No real patient data, no PHI. 13 columns in total.
- **Label (demo).** Binary readmission flag, generated by thresholding a hand written risk score at its 85th percentile (about 15% positive).
- **Clean evaluation data (`reevaluation/`).** Diabetes 130-US Hospitals dataset (UCI Machine Learning Repository, dataset 296, Strack et al. 2014), 69,970 first encounters after cohort filtering. This dataset was used only for the clean re evaluation; it was not the hackathon's data.

## Model

- **Algorithm.** XGBoost classifier (`xgboost.XGBClassifier`).
- **Demo training procedure.** 80/20 train/test split (random_state 42, no stratify), fixed hyperparameters, single machine.
- **Explainability.** SHAP TreeExplainer; top features surfaced per prediction in the Streamlit app.

## Evaluation

Measured 2026-10-22. Full detail in `reevaluation/results.md`.

| Evaluation | Accuracy | ROC AUC | PR AUC |
|---|---|---|---|
| Synthetic demo, leaked feature removed (held out n = 10,000) | 0.9250 | 0.96094 | 0.83147 |
| Real data, UCI Diabetes 130, tuned XGBoost (held out n = 13,994) | 0.9097 | 0.6517 (95% CI 0.6354 to 0.6678) | 0.1717 |
| Real data, logistic regression baseline | 0.6224 | 0.6326 | 0.1553 |

The tree model accuracy figures on real data sit close to the 91.03% majority class rate; ROC AUC and PR AUC are the informative numbers.

An earlier version of this project advertised 0.96 accuracy and 0.99 AUC. Those figures came from a label derived feature (see limitations) and have been removed. They were not real measurements.

## Limitations and known risks

- **Removed leaked feature.** Version 0.1 of the demo added the label generating risk score back in as a feature named `risk_index_composite`, in training and in the app at inference time. The feature and the claim built on it were removed in October 2026. The ablation is documented in `reevaluation/results.md` (Part A).
- **App model file.** The Streamlit app still loads the original hackathon model artifact, which was trained with the leaked feature. Its scores are a UI demo only.
- **Synthetic demo data.** The demo training data is not real EHR data. Performance on real clinical data is characterized only by the UCI re evaluation above.
- **Distribution shift.** No external validation across hospital systems, geographies, or time periods.
- **Subgroup performance.** Per subgroup metrics are not reported for the demo. The UCI re evaluation reports SHAP rankings as produced, including two gender indicators ranking high, which needs examination before any interpretive claim.
- **Interpretation.** SHAP values explain *the model*, not clinical causation. They do not justify clinical action.
- **Calibration.** Calibration was measured for the clean UCI pipeline (slope 1.0247, intercept minus 0.0787, Brier 0.0795; see `reevaluation/results.md`). The demo model's probabilities are not calibrated.

## Ethical considerations

- Hospital readmission models can encode structural inequities present in healthcare data (access patterns, documentation differences). A production version would require fairness audits, calibration assessment per subgroup, and clinician oversight.
- Treating any model output as a clinical recommendation without expert review is unsafe. The Streamlit app is a UX demonstration, not a clinical tool.
